# ИИ-агент: текст задания → деталь КОМПАС-3D

```
текст задания ──► LLM (5 вариантов) ──► JSON на мини-языке операций (DSL)
                                           │
                    независимый расчёт объёма/габарита (NumPy, refgeom)
                                           │
                голосование + самопроверка габарита + запросы на исправление
                                           │
              КОМПАС-3D через COM ──► сверка КОМПАС ↔ расчёт ──► .m3d
```

Модель не пишет код для API КОМПАСа — она выдаёт короткое описание операций
(`prompts/system.md`), а строит его детерминированный исполнитель. Это главное,
что даёт точность на слабой Flash-модели.

## Установка (Windows, Python 3.10–3.12)

```
pip install -r requirements.txt
copy .env.example .env        # вписать AITUNNEL_API_KEY
copy banned_terms.example.txt banned_terms.txt   # вписать запрещённые слова (файл не коммитится)
```

## Порядок запуска

1. **Калибровка КОМПАСа** (КОМПАС должен быть установлен):
   `python kompas_selftest.py`
   Находит знаки осей плоскостей XZ/YZ и единицы объёма, затем строит 11 эталонных
   деталей и сверяет с точным расчётом. Цель — «ВСЁ СОВПАЛО».
   Исполнитель КОМПАСа (`agent/kompas_exec.py`) писался без доступа к КОМПАСу:
   если какая-то операция падает, запишите её макросом в КОМПАСе / найдите пример
   в SDK и поправьте соответствующий короткий метод (`prism`, `revolve`, `measure`, `edge`).
2. **Проверка на своём наборе без КОМПАСа:** `python eval.py`
   15 заданий с эталонами в `tests/tasks.jsonl`. Печатает «ИТОГО: x/15 = N %».
   Гоняйте после каждой правки промпта. Добавляйте свои задания в `tests/make_tasks.py`
   (`python -m tests.make_tasks` пересчитает эталоны).
3. **Полный прогон:** положите задания в папку `tasks/` (по одному .txt) или в один файл
   («Задание 1. …», «Задание 2. …» или разделитель `---`) и запустите
   `python run.py tasks/` → `out/*.m3d`, `out/summary.csv`, `out/журнал_запросов.jsonl`.

Одна команда `python run.py <файл_с_заданиями>` строит все детали подряд.
Модель по умолчанию задаётся в `config.yaml`.

## Тесты без сети и КОМПАСа
```
python -m tests.test_refgeom     # точность расчёта на деталях с известным объёмом (≈0,01 %)
python -m tests.test_pipeline    # голосование, исправления, обезличивание
python eval.py --replay          # конвейер целиком на эталонных ответах
```

## Как улучшать (по убыванию пользы)
- Смотрите `out/eval_report.json` на проваленных заданиях: что модель поняла не так →
  добавьте правило или пример в `prompts/system.md`.
- Сочините 20–30 заданий своих (простые детали, все размеры названы).
- Число вариантов `n_samples` 5→7 повышает надёжность (Flash дешёвая).
- Если чего-то не хватает в языке операций — новый тип фигуры добавляется в
  `agent/dsl.py` (`shape_to_contour`), исполнители менять не нужно, если фигура состоит из отрезков и дуг.

## Защита данных
- Ключи — только в `.env`; модель и провайдер — в `config.yaml` (переключение без правки кода, `--model`).
- Перед каждым запросом `agent/privacy.py` удаляет названия изделия/проекта/организации/фамилии
  (список — в локальном `banned_terms.txt`, в git не попадает; режим `block` — вообще не отправлять).
- Журнал всех запросов: `logs/requests.jsonl` — время, модель, отправленный текст, ответ, токены,
  что было обезличено. В модель уходит только геометрия («пластина 60×40×3 с отверстиями»).
- Задания, модели, чертежи, журнал хранятся только локально.

## Как агент проверяет себя
1. Схема операций проверяется до построения; ошибка с понятным текстом уходит модели на исправление.
2. Независимый точный расчёт объёма и габарита каждого варианта.
3. Сравнение с габаритами, которые модель сама вывела из задания (`bbox_expected`), и с числами из текста.
4. Голосование 5 вариантов; при расхождении — повторный запрос с конкретными цифрами.
5. Сверка КОМПАС ↔ независимый расчёт; при расхождении строится следующий вариант.
6. Файл переоткрывается после сохранения.

## Формообразование (новые операции)
| Операция | Что делает | Как считается проверка |
|---|---|---|
| `shaft`/`revolve`/`torus` + `"axis":"X"/"Y"` | тела вращения с горизонтальной осью | точно |
| `tilt` у `extrude`/`cut`/`holes` | наклонные плоскости, отверстия под углом | точно |
| `extrude` + `"draft"` | выдавливание с уклоном (пирамиды, литейные уклоны) | точно для многоугольников, < 0,02 % для дуг |
| `loft` | тело по сечениям (квадрат → круг и т. п.) | точно при одинаковом числе сторон, иначе ≈ (допуск 1 %) |
| `sweep` | пруток/труба по плоской ломаной с гибами | теорема Паппа — Гульдина + сетка |
| `shell` | тонкостенный корпус (коробка, стакан) | точно |

Первый запуск на компьютере с КОМПАСом: `py kompas_formdiag.py` — проверит новые операции и подберёт их настройки
(направление уклона, режим кинематики, способ построения наклонной плоскости).

## Чертежи по ГОСТ: только габаритные, установочные, присоединительные, эксплуатационные размеры
`py make_drawings.py out_module` — габаритный чертёж (ГЧ) по ГОСТ 2.102 / 2.109-73. Программа находит все возможные
размеры и описывает их назначение; модель по правилам `prompts/drawing.md` выбирает нужные (габариты — всегда),
установочные и присоединительные ставятся с отклонениями ±0,2. `--no-llm` — выбор программой, `--type full` — прежний режим.
